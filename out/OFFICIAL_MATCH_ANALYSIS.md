# 공식 공개 경기 분석 (Official match analysis)

> **English summary.** All 71 public "내 경기" replays available for this project (Y side only) are collected in
> [`official-replays/`](official-replays/). Games 01–19 were played by submission **v2** (4W–15L), games 20–47 by
> submission **v3** (8W–20L), games 48–59 (9/29 22:00 round) by **v6's code** (4W–8L): the v6 source reproduces all 1,738 recorded
> Y command turns of these 12 games exactly (§9), and games 60–71 (9/30 10:00 round) were also played by v6's code (6W–6L,
> all 1,650 turns reproduced; the midgame flip mechanism of §9 recurs, §10). Which site submission number carried that code was not checked on the site.
> Nothing here is a claim about v4/v5 or the local only candidates. Opponent strategies are private; every statement about them is an
> inference from public replay observations and is marked as such.

이 문서는 공식 사이트 `내 경기`에서 내려받은 공개 리플레이 **71경기**의 분석을 한 곳에 모은 것이다. 이전에 회차별 보고서(`heartbeat-*`)와
독립 에이전트 분석, 판단 정책 실험 보고서에 나뉘어 있던 경기 관련 관찰을 모두 여기로 옮겼고, 회차별 보고서는 삭제했다.
로컬 검증(대체 상대 대전)의 방법과 결과는 [`experiments/`](experiments/)의 각 README에 있다. **로컬 승률은 실제 상대 팀의 승률이 아니다.**

## 1. 범위와 버전 귀속

- 47경기 모두 **Y 진영**(리플레이의 `side`), 실행 오류 없음(기록된 명령 상태 3,813개 전부 `ok`), 몰수 0. 서버 응답 시간(`myResponseMs`): 첫 턴 최대 546 ms, 이후 턴 최대 69 ms.
- **버전 귀속**: 01–19 = **v2**, 20–47 = **v3**. 근거는 리플레이에서 Y의 초반(1–15턴) 최대 깃발병 수다: 01–19는 모두 **12**(v2의 상한), 20–47은 모두 **6**(v3의 상한).
  이는 사이트에 표시된 제출 번호(#2, #3)와 일치한다. `evaluationId`(UUIDv7)의 시각은 평가 **슬롯** 시각이라 제출 시각이 아니다
  (20–35번이 v3 제출 11:24보다 이른 9/28 08:00 KST로 찍혀 있다). 그래서 이 값은 버전 판정에 쓰지 않았다.
- **공개 회차** 표기는 같은 슬롯 시각으로 묶은 그룹(01–13 / 14–19 / 20–35 / 36–47)이며, 이전에 기록된 회차별 전적과 정확히 일치한다:

- **상대 풀 변경**: 9/29 10:00 회차부터 상대 풀이 학교 구분 없이 전체 참가팀으로 넓어졌다(공식 공지; 에이전트에 전달되는 진영 정보는 기존 기준 유지). 36–47번의 승률은 그 전 회차와 같은 분포의 성능 변화로 읽지 않는다.
- 48–59번(9/29 22:00 회차, 12경기)은 **v6 코드**가 치렀다. 근거는 명령 재현이다: 공개 관측을 턴마다 v6 소스에 넣으면 기록된 Y 명령이
  12경기 1,738턴 모두 순서까지 똑같이 나오고, v3·indep-v0·v4/v5 유사 소스는 1–3턴에 갈라진다(§9.1). 초반 최대 깃발병 수도 모두 **10**(v6의 상한).
  이 코드가 사이트의 어느 제출 번호였는지(v6인지, 같은 코드의 다른 업로드인지)는 사이트에서 확인하지 못했다. 기록된 v5 ZIP(11.2 KiB)은 v6 ZIP(10.2 KiB)과 크기가 달라 같은 파일이 아니다.
- v4·v5나 로컬 후보(cap7, indep-v0)가 치른 공식 경기는 **없다**. §3–§8의 결론은 v2·v3 코드, §9는 v6 코드에 대한 것이다.

## 6. 공식 31·34번에 대한 반사실적 명령 비교

[`official_cases.py`](experiments/6-decision-policies%28cap7%29/official_cases.py)가 저장된 공개 관측을 후보 정책에 입력한다. 두 경기에서 검사한 6개 턴 모두 v3의 실제 명령이 **정확히 재현**됐다.
31번 30턴: v3 `F 2/W 1`, 같은 관측의 cap7 `F 3/W 0`, 적응 생산 `F 1/W 4`. 40턴: v3·cap7 `F 2/W 0`, 적응 생산 `F 0/W 3`. 34번 20턴: v3 `W 13`, cap7·적응 생산 `F 1/W 11`.
이는 **한 턴의 반사실적 판단**일 뿐이다(적응 후보의 손실 메모리는 0으로 초기화). 후보가 그 전 턴부터 실행됐다면 이후 상태와 적 행동이 달랐을 것이므로 공식 결과 개선을 주장하지 않는다.
31번 기록: 위협받은 내 건물 229건물·턴 중 인접 W가 있던 경우는 31건이었고, 20턴 중앙광장 (7,7)도 인접 방어 W가 없는 위협 지점이었다.

## 7. 불확실성과 해석 한계

1. 상대 팀의 명령·전략은 공개되지 않는다. 표와 §3.5의 K 관련 서술은 공개 관측의 집계이며 의도는 추정이다. K의 점수는 공개 JSON에서 `null`인 턴이 있어 추정하지 않았다.
2. 표본은 v2 19경기, v3 28경기이며 상대 팀이 겹친다. 9/29 10:00부터 상대 풀이 바뀌었다(§1). v2·v3 사이의 차이는 통계적으로 구분되지 않는다.
3. 20턴 전투병 열세와 패배의 연관은 강하지만 인과가 아니다(34, 38, 37번 등 반례). 병력은 이전 교전의 결과이기도 하다.
4. 버전 귀속은 깃발병 상한 서명(12/6)과 사이트 제출 번호에 근거한다. `evaluationId` 시각은 사용하지 않는다.
5. 로컬 대체 상대(v2·v3의 상수 변형, 공식 Lv2, 독립 에이전트의 변형)는 실제 팀 봇이 아니다. 어떤 로컬 승률도 실제 상대 팀 승률로 해석하지 않는다.
6. v4·v5의 공식 경기 기록은 이 저장소에 없다. v6 코드의 기록은 12경기(§9)뿐이다. v5는 마지막 기록 시점(9/29 13:25)에 대회용으로 선택되어 있었으나 소스가 이 작업 공간에 없다.
